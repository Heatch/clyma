# Clyma

Clyma is a climate-risk prediction market on Solana Devnet. It combines an
interactive geographic globe with a pooled binary market program: users explore
climate scenarios generated by the Model forecast engine, inspect evidence and resolution rules,
connect a Phantom-compatible wallet, and trade YES or NO positions in Devnet SOL.

> **Prototype only.** Clyma is not a production financial service. Devnet SOL
> has no monetary value.

## Quick start

```bash
npm install
cp .env.example .env
# Fill in BACKBOARD_API_KEY in .env (SQLITE_PATH defaults to ./data/clyma.db)
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

To seed markets, check chain readiness then run the seeder:

```bash
node scripts/preflight.mjs
node scripts/lifecycle.mjs seed
```

## Market data

Markets are generated by the model (see `callModel` in `scripts/lifecycle.mjs`), assigned
deterministic trade tapes (`scripts/lib/tape.mjs`), funded on-chain at exact
tape totals, and indexed in SQLite via `node scripts/lifecycle.mjs seed`.
Check chain readiness first:

```bash
node scripts/preflight.mjs
```

## Pooled binary market model

YES and NO deposits enter one program-owned market vault. Before resolution:

```
YES probability = total YES pool / total market pool
NO probability  = total NO pool  / total market pool
```

After an authorized resolver records an outcome, each winning wallet receives a
proportional share:

```
user payout = user winning position × total market pool ÷ total winning-side pool
```

The program uses `u128` arithmetic with checked math, rounding down to whole
lamports. Cancelled markets allow reclaiming original deposits.

Serving markets requires `BACKBOARD_API_KEY` (generation + forecasts). Locally
the database is a SQLite file — no DB server needed. Bare `node scripts/*`
invocations need `NODE_OPTIONS=--experimental-sqlite` (npm scripts and
`start-app.bat` set this automatically).

## Cloudflare deployment (production)

Production runs on the Cloudflare free tier: the Next.js app as a Worker
(`@opennextjs/cloudflare`) with data in D1. The local SQLite path stays for
`npm run dev`, tests, and offline scripts.

One-time setup (already done for `clyma`):

```bash
npx wrangler login
npx wrangler d1 create clyma          # paste database_id into wrangler.jsonc
npx wrangler secret put JWT_SECRET    # and BACKBOARD_API_KEY
node --experimental-sqlite scripts/export-d1-sql.mjs
npx wrangler d1 execute clyma --remote --file data/d1-import.sql --yes
```

Deploy and preview:

```bash
npm run cf:build     # next build + Worker bundle (no deploy)
npm run cf:preview   # build + run the Worker locally (workerd + local D1)
npm run cf:deploy    # build + deploy to Cloudflare
```

Local preview secrets live in `.dev.vars` (gitignored, `KEY=value` lines);
production secrets live in the Worker. Runtime configuration (model id,
predict guards) is in `wrangler.jsonc` `vars`; `NEXT_PUBLIC_*` values are
inlined at build time, so changing the RPC or program id needs a redeploy.

`clyma.xyz` is attached as a custom domain (Cloudflare dashboard → Workers
& Pages → clyma → Settings → Domains & Routes). The Worker also stays
reachable at `https://clyma.<account>.workers.dev` as a fallback.

To verify a deployment:

```bash
curl -s https://clyma.xyz/api/markets?limit=1        # 200, total = market count
curl -s https://clyma.xyz/api/markets/<id>/history    # merged tape + snapshots
curl -s -X POST https://clyma.xyz/api/auth/challenge \
  -H "content-type: application/json" \
  -d '{"walletAddress":"8qFS3dgQGZ614c2owwobfT5qjZnSxMgb6Wg2abh7b75i"}'  # 64-char nonce (D1 write)
npx wrangler tail clyma                               # live requests + CPU/errors
```

`www.clyma.xyz` has no DNS record; add a `www` record plus a Redirect Rule
to the apex in the dashboard if you want it to answer.

Docker (`Dockerfile`, `docker-compose.yml`, the `cloudflared` tunnel) is no
longer used in production — it remains as a self-hosted fallback and uses
the local SQLite file.

### Lifecycle scripts against D1

Scripts run from any machine with a funded Devnet wallet; with these
variables set they read/write the deployed database instead of the local
file (otherwise they use `SQLITE_PATH`):

```env
CLOUDFLARE_ACCOUNT_ID=...
CLOUDFLARE_D1_DATABASE_ID=...
CLOUDFLARE_API_TOKEN=...   # D1 edit permission
```

Then `node scripts/lifecycle.mjs close|resolve|roll|boost` operates on
production. Keep a Devnet wallet at `~/.config/solana/id.json` for the
on-chain side.

## Devnet deployment

1. Fund a Devnet wallet:

   ```bash
   solana config set --url devnet
   solana airdrop 2
   ```

2. Deploy the program:

   ```bash
   anchor deploy --provider.cluster devnet
   ```

3. Seed markets (generates definitions, builds tapes, funds pools, indexes SQLite):

   ```bash
   node scripts/preflight.mjs
   node scripts/lifecycle.mjs seed --dry-run   # plan only, no writes
   node scripts/lifecycle.mjs seed
   ```

   Useful flags: `--markets N`, `--budget SOL`, `--base-id ID`,
   `--fixture-file PATH` (replay saved definitions offline), `--reset`,
   `--skip-chain`, `--skip-db`, `--dry-run` (plan only, no writes).

4. Set `NEXT_PUBLIC_PROGRAM_ID` in `.env` and start the app.

## Market lifecycle

Markets expire, resolve, and renew via `scripts/lifecycle.mjs` (see
`docs/DEMO.md` for the full runbook):

```bash
node scripts/lifecycle.mjs close     # shut expired markets
node scripts/lifecycle.mjs resolve   # settle due markets by seeded draw
node scripts/lifecycle.mjs roll      # close + resolve + top up to 100 open
```

Outcomes are deterministic draws against each market's model odds — never
hand-picked. Resolution is permissioned (this wallet is the resolver); there
is no oracle or dispute process.

## AI probability forecasts

`POST /api/predict` asks the Model (GPT Luna via Backboard) for a calibrated
YES probability from the market question, its resolution rules, and any
caller-supplied context. The result drives the opening probability of newly
created markets.

- Uses `BACKBOARD_API_KEY` and `LLM_MODEL` (default `gpt-5.6-luna`), the same
  credentials as market generation
- Output is validated as a float in `[0.00, 1.00]`; anything else falls back to `0.5`
- No live web retrieval: callers may pass their own `news_context`
- No fallback provider: when the model is unreachable the route returns 502
  and the Model forecast simply does not render

## Security

- No private keys or seed phrases are requested or stored
- Wallet signatures remain inside the browser adapter
- Deterministic PDAs with Anchor constraints
- Checked arithmetic on all pool operations
- On-chain state is authoritative — not browser storage or API metadata

## Known limitations

- Resolution is permissioned; no oracle or dispute process
- No order book or limit orders (pooled model only)
- Integer settlement can leave sub-lamport dust in vaults
- Only Phantom wallet and native SOL are wired
- Anchor tests require Rust, Solana CLI, and a local validator
